# Deep-native recovery V1

`Deep.Protocol.Native` is a consumer-unreferenced dark path for the Deep-native clean break. It is
not a Session compatibility surface and it is not yet part of any production package or client.

## Recovery phrase

- Entropy is exactly 256 bits from the platform CSPRNG.
- The phrase is exactly 24 words from the canonical English BIP-39 list.
- Encoding and checksum are BIP-39 compatible; input is NFKD-normalized and canonical output is
  lower-case words separated by one ASCII space.
- V1 intentionally has no user passphrase. The PBKDF2 salt is exactly `mnemonic`, avoiding an
  undeclared second recovery secret and ambiguous restore UX.
- Twelve-, fifteen-, eighteen-, and twenty-one-word wallet phrases are rejected even if they are
  otherwise valid BIP-39 mnemonics.

The BIP-39 seed is not used directly as an account or device key. HKDF-SHA-512 derives four
role-separated 32-byte seeds from an exact `networkId16 || accountGenerationBE64` context:

- account signing;
- future account PQ signing;
- recovery authorization;
- backup wrapping.

Device keys remain independently generated CSPRNG material. V1 never converts Ed25519 material to
X25519 and never exports role seeds through the public API. Secret-owning capabilities zero their
managed buffers on disposal; callers must still avoid logging, telemetry, clipboard persistence,
screenshots, crash dumps, and immutable string copies of recovery data.

## Post-quantum status

The PQ role seed is only reserved domain-separated material. It does not instantiate ML-KEM,
ML-DSA, a handshake, or a ratchet. No provider is selected, and the project has no PQ dependency.
All PQ suites remain dark and production-ineligible until the v3 program's provider, independent
implementation, vector, platform, protocol-state, and external-review gates pass.

## Evidence

- The embedded English word list is pinned by SHA-256 and count.
- A checked-in vector is generated by an independent Python standard-library PBKDF2/HKDF oracle.
- Tests cover checksum/word/count rejection, normalization, context and role separation, defensive
  copies, zeroization, and the absence of public seed/constructor surfaces.
- The project is deliberately unreferenced by all consumer projects. Enabling it requires an
  explicit later cutover decision; no runtime negotiation or fallback is permitted.
